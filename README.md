# 📚 Library: консольна система обліку бібліотеки

Навчальний проєкт на C# : облік видань і читачів міської бібліотеки.

## Можливості

- Чотири типи видань: **книга**, **електронна книга**, **науковий журнал**, **дитяча книга**
- Видача видання читачу, **якщо в нього немає прострочених повернень**
- Ліміт примірників (для електронних книг ліміту немає)
- Автоматичний розрахунок штрафу під час повернення
- Перегляд того, що зараз на руках у читача
- Швидкий пошук читача за номером квитка
- Пошук видань за назвою або автором (за частиною тексту, без урахування регістру)
- **Скасування останньої дії** (Undo): видача, повернення, додавання читача чи видання
- Зрозумілі повідомлення про помилки (читача чи видання не знайдено, немає примірників тощо)

## Правила бібліотеки

| Тип видання      | Термін видачі | Штраф за запізнення                              |
|------------------|---------------|--------------------------------------------------|
| Книга            | 14 днів       | 20 грн/день                                      |
| Електронна книга | 14 днів       | 10 грн/день                                      |
| Науковий журнал  | 3 дні         | 50 грн/день перші 7 днів, далі 100 грн/день      |
| Дитяча книга     | 21 день       | 10 грн/день                                      |

### Ключові рішення

- **Поліморфізм замість `if (тип == ...)`.** Спільне (назва, автор, рік, облік примірників) живе в `LibraryItem`, а термін видачі й формула штрафу перевизначаються в підкласах. `LibrarySystem` не знає, який саме тип видання перед ним.
- **`Dictionary<int, Reader>`** для пошуку читача за номером квитка за O(1).
- **`Stack<ILibraryAction>`** для Undo: остання виконана дія скасовується першою (LIFO). Кожна дія вміє себе відкотити.
- **Логіка відокремлена від консолі.** `LibrarySystem` повертає результат або кидає `LibraryException`; друкує лише `Program`. Це дозволяє тестувати логіку.
- **Час можна підмінити:** `new LibrarySystem(() => new DateTime(2025, 1, 1))`, що зручно для перевірки штрафів.
